# qualWeldChit — план разработки

## О проекте

Генератор документов. Пользователь загружает xlsx-файл с данными, выбирает
метод контроля, нажимает "Сгенерировать" — программа находит нужные шаблоны,
подставляет в них данные из xlsx и упаковывает результат в zip-архив,
который можно скачать.

## Стек

- Фронт: React, CSS modules, Vite
- Бек: Node.js, Express
- Кроссплатформенность: macOS и Windows (важно для путей к файлам!)

## Принцип работы (коротко)

1. Пользователь загружает xlsx (drag&drop).
2. Пользователь выбирает метод контроля (ВИК / РК / ПВК).
3. По кнопке "Сгенерировать" бэкенд:
   - читает xlsx построчно;
   - для каждой строки определяет путь к шаблону:
     `templates/<цифра из "Квалификация">/<буквы из "Способ сварки">`;
   - подставляет плейсхолдеры в шаблон;
   - сохраняет файл с именем:
     `<ФИО>, <способ сварки>(<цифра квалификации>) №<Номер>-ОК-<метод контроля>`;
   - складывает все файлы в zip. Имя архива = цифра из имени входного xlsx.
4. Пользователь жмёт "Скачать архив".

## Плейсхолдеры шаблона

| Плейсхолдер   | Колонка xlsx        |
|---------------|----------------------|
| `{{number}}`  | Номер                |
| `{{i_day}}`   | Дата контроля         |
| `{{company}}` | Организация           |
| `{{fio}}`     | ФИО                   |
| `{{w_day}}`   | Дата сварки           |
| `{{lable}}`   | Клеймо                |

Плюс служебные колонки (не подставляются напрямую, а используются для логики):
- **Квалификация** — из текста ячейки нужно вытащить одну цифру.
- **Способ сварки** — из текста ячейки нужно вытащить буквы (например, "РД").

## План сессий

### Сессия 1 — Каркас проекта
- Создать структуру папок: `client/` (Vite + React) и `server/` (Express).
- Настроить простой Express-сервер с одним тестовым роутом (`GET /api/ping`).
- Настроить Vite-проект, проверить, что фронт стучится на бэк (fetch `/api/ping`).
- Настроить общий `package.json` со скриптами запуска (или два отдельных —
  что проще для новичка).
- Результат: пустой, но рабочий фронт + бек, которые видят друг друга.

### Сессия 2 — Чтение xlsx на бэкенде
- Подключить библиотеку для чтения xlsx (например `xlsx`/`exceljs` — выбрать
  самую простую в использовании).
- Написать функцию, которая читает файл из `input_example` и построчно
  выводит в консоль нужные колонки (Номер, Дата контроля, Организация, ФИО,
  Дата сварки, Клеймо, Квалификация, Способ сварки).
- Написать простую функцию извлечения:
  - цифры из текста ячейки "Квалификация";
  - букв (метода сварки) из текста ячейки "Способ сварки".
- Результат: скрипт, который печатает в консоль массив готовых объектов
  по каждой строке xlsx.

### Сессия 3 — Работа с шаблоном
- Разобраться, как физически устроен файл-шаблон в `templates/2/РД`
  (docx с плейсхолдерами вида `{{number}}`).
- Подключить библиотеку для подстановки данных в docx (например `docxtemplater`).
- Написать функцию: взять путь к шаблону + объект с данными строки →
  вернуть готовый docx-буфер/файл.
- Проверить на одном шаблоне и одной строке из xlsx вручную.
- Результат: функция `fillTemplate(templatePath, data) → buffer`.

### Сессия 4 — Логика путей и имён файлов
- Функция построения пути к шаблону:
  `templates/<цифра квалификации>/<буквы способа сварки>`.
- Функция построения имени выходного файла:
  `<ФИО>, <способ сварки>(<цифра>) №<Номер>-ОК-<метод контроля с фронта>`.
- Обязательно использовать кроссплатформенные утилиты для путей
  (`path.join`, а не ручную склейку строк со слэшами) — из-за macOS/Windows.
- Обработать "плохие" символы в имени файла (недопустимые в Windows: `\ / : * ? " < > |`).
- Результат: две чистые функции с юнит-проверкой на паре примеров.

### Сессия 5 — Сборка zip-архива
- Подключить библиотеку архивации (например `archiver`).
- Написать функцию: список сгенерированных файлов (буфер + имя) → zip-архив.
- Имя архива = цифра, извлечённая из имени входного xlsx-файла.
- Результат: функция `buildZip(files) → zipBuffer`, архив открывается и
  файлы внутри читаемы.

### Сессия 6 — API-эндпоинты
- `POST /api/generate` — принимает xlsx (через `multer` или аналог) и метод
  контроля, прогоняет всю цепочку (чтение → шаблон → имена → zip),
  сохраняет результат во временную папку, возвращает id генерации.
- `GET /api/download/:id` — отдаёт готовый zip-архив.
- Простая обработка ошибок (файл не xlsx, нет нужного шаблона и т.д.) —
  понятные сообщения об ошибке в JSON.
- Результат: API можно проверить через Postman/curl без фронта.

### Сессия 7 — Фронтенд: форма

- Кнопка "Скачать архив" (появляется/активируется после успешной генерации).
- Стили через CSS modules, максимально простая вёрстка.
- Результат: форма визуально готова, но пока не связана с реальным API

## Договорённости по стилю кода (для новичка)

- Без сложных абстракций: обычные функции, без классов, без сложных паттернов
  проектирования.
- Каждая функция делает одну понятную вещь (парсинг, генерация имени,
  подстановка в шаблон, архивация — всё отдельно, легко тестировать вручную).
- Комментарии на русском там, где логика неочевидна (особенно регулярки для
  извлечения цифры/букв из ячеек).
- Минимум зависимостей: одна библиотека на задачу (xlsx, docxtemplater,
  archiver, multer), без лишнего.
